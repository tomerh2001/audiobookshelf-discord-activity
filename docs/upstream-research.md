# Audiobookshelf integration evidence

Verified on 2026-11-19 using official Audiobookshelf and Authentik source through GitHub MCP. These are upstream capabilities and implementation constraints, not claims of completed end-to-end deployment.

## Version and synchronization

The current stable release is [Audiobookshelf v2.38.0](https://github.com/advplyr/audiobookshelf/releases/tag/v2.38.0), published on 2026-11-17. Pin native-client integration to commit `1430c9fc642d586ff91c8d4cbed20aab2c47e473`. Its release notes describe the v3 React client as a testing preview, so the stable Vue/Nuxt client remains the integration target.

The inspected stable source has no native group listening or SyncPlay protocol. Its `sync` endpoints save listening progress; they do not coordinate playback between users. This conclusion follows from the complete [API router](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/routers/ApiRouter.js), [SocketAuthority](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/SocketAuthority.js), and [PlaybackSessionManager](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/managers/PlaybackSessionManager.js). The activity must own room membership, host controls, queue state, synchronized start/pause/seek/rate, drift correction, and reconnect recovery while using native playback sessions and players.

## Playback API and media

| Request | Behavior |
| --- | --- |
| `POST /api/items/:id/play` | Start an audiobook session. |
| `POST /api/items/:id/play/:episodeId` | Start one podcast episode. |
| `GET /api/session/:id` | Read an open session owned by the authenticated user, or accessible to an admin. |
| `POST /api/session/:id/sync` | Save `{currentTime,timeListened,duration?}`; time values are seconds. |
| `POST /api/session/:id/close` | Close a session, optionally applying the same progress payload first. |

The start body accepts `deviceInfo` (including `deviceId` and `clientName`), `supportedMimeTypes`, `mediaPlayer`, `forceTranscode`, and `forceDirectPlay`. The response includes `id`, `currentTime`, `duration`, `playMethod`, `audioTracks`, `chapters`, and expanded `libraryItem` data. Play methods are `0` direct, `1` direct stream, `2` transcode, and `3` local. Source: [PlaybackSessionManager](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/managers/PlaybackSessionManager.js), [playback response](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/objects/PlaybackSession.js), [constants](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/utils/constants.js).

Starting playback closes existing sessions for the same Audiobookshelf user **and device**. Community participants therefore need distinct device IDs. Separate sessions still write the same per-user/item progress record. Followers on a shared community account must not repeatedly overwrite that record. A designated progress writer or disabled community progress persistence is required.

The native `PlayerHandler.prepare()` starts replacement playback without explicitly closing its previous session; the upstream server performs that replacement. Replace the gateway's previous session mapping after a successful start so ordinary queue advancement does not accumulate stale session capabilities or hit a fixed session limit.

Direct `audioTracks[].contentUrl` values use `/api/items/:id/file/:ino`; each track has a `startOffset` for the book-wide timeline. The native player instead uses `/public/session/:sessionId/track/:index`. This capability endpoint has no bearer check and stays available while the session is open. It uses Express `sendFile`, including normal byte-range handling. A transcode track uses `/hls/:sessionId/output.m3u8`, with six-second MPEG-TS segments such as `output-12.ts`. HLS requests also use the open session as a capability. Source: [Book.getTracklist](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/models/Book.js), [SessionController.getTrack](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/controllers/SessionController.js), [HlsRouter](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/routers/HlsRouter.js), [Stream](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/objects/Stream.js).

The gateway must preserve streaming and `Range`/`If-Range`, constrain requested media to the participant's sessions, and keep upstream credentials out of browser URLs and payloads. Session IDs grant access to upstream public media and require the same care as media capabilities. Do not use a general upstream URL proxy. The item middleware checks library access before starting playback; the session middleware checks session ownership. Source: [LibraryItemController](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/controllers/LibraryItemController.js), [SessionController](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/controllers/SessionController.js).

## Native web integration

The stable client is a Nuxt 2/Vue 2 static SPA. Run `npm ci` and `npm run generate` inside upstream `client` to produce `client/dist`. `ROUTER_BASE_PATH` controls router and API paths; the upstream default is `/audiobookshelf`. The default layout connects Socket.IO over WebSocket at `${routerBasePath}/socket.io`. Source: [client/package.json](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/package.json), [nuxt.config.js](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/nuxt.config.js).

There is no supported embedded-player control API in the inspected source. Integrate through a small, reproducible patch against the pinned source:

- `MediaPlayerContainer.vue` owns `playerHandler`, constructed from `PlayerHandler`. The default layout exposes the container as `$refs.mediaPlayerContainer`.
- `PlayerHandler.load(item, episodeId, playWhenReady, playbackRate, startTimeOverride)` opens the item. `play`, `pause`, `seek(seconds, shouldSync)`, `setPlaybackRate`, and `getCurrentTime` expose playback controls.
- The event bus accepts `play-item` with `{libraryItemId,episodeId,startTime,queueItems}`, `pause-item`, `playback-seek`, `playback-time-update`, and `play-queue-item`.
- `LocalAudioPlayer` manages `#audio-player`, multi-file offsets, native HLS fallback, and hls.js. Apply commands through `PlayerHandler` so global book time remains correct across tracks.
- Vuex uses `user/setUser`, `user/setAccessToken`, and `user/getToken`; Axios obtains the bearer from that store. A gateway session can substitute a scoped local capability while the backend retains ABS credentials.

Source: [MediaPlayerContainer](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/components/app/MediaPlayerContainer.vue), [PlayerHandler](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/players/PlayerHandler.js), [LocalAudioPlayer](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/players/LocalAudioPlayer.js), [AudioTrack](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/players/AudioTrack.js), [Axios plugin](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/plugins/axios.js).

Native Socket.IO authentication emits `auth` with the token and receives `init` or `auth_failed`. Playback events include `stream_open`, `stream_closed`, `stream_progress`, `stream_ready`, `stream_reset`, `stream_error`, and `user_session_closed`. `user_item_progress_updated` is sent to every connection for the same ABS user. In the default layout, a different session updating the same item causes a warning while playing and an automatic seek while paused. Community rooms need filtering so native cross-device progress does not fight room synchronization. `stream_reset` can be broadcast beyond its owner; filter by the participant's session. Source: [default.vue](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/layouts/default.vue), [SocketAuthority](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/SocketAuthority.js), [HlsRouter](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/routers/HlsRouter.js).

Payload shapes differ: `stream_progress` identifies its session in `stream`; `stream_error` uses `id`; `stream_reset` uses `streamId`; `stream_closed` is a session-ID string. `stream_ready` has no payload and cannot be scoped by a session identifier. Translate every forwarded session identifier to the gateway's opaque alias. Source: [Stream.js](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/objects/Stream.js).

Audiobookshelf normally sends CSP `frame-ancestors 'self'` unless `allowIframe` is enabled. Serving the pinned client locally through the activity gateway avoids depending on a foreign-origin iframe; the activity itself must provide the appropriate Discord frame policy. Source: [Server.js](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/Server.js).

## Native client compatibility checks

The pinned native browser requires several response fields that are easy to remove accidentally while sanitizing. Preserve `permissions.accessAllLibraries`: accounts with this permission normally have an empty `librariesAccessible`, and forcing the permission to false prevents the native library store from opening any library. Keep administrative write permissions disabled independently. Replace `coverPath` and author `imagePath` with a non-sensitive presence marker; native components use these fields to decide whether to request the scoped `/cover` or `/image` endpoint. Removing them hides valid artwork. Source: [user store](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/store/user.js), [cover getters](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/store/globals.js), [author image component](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/components/covers/AuthorImage.vue).

Native multi-selection queues use `POST /api/items/batch/get` with `{libraryItemIds:[...]}`. This is a read, distinct from batch edit/delete routes. Collection conversion uses `POST /api/playlists/collection/:collectionId`; playlist mutation middleware checks account ownership. Podcast progress reads use `GET /api/me/progress/:itemId/:episodeId`. Continue Listening hide/readd actions are unusual **GET requests that mutate state**; apply the community progress writer rule to them too. Chapter metadata arrives in the expanded item and playback session; chapter seeking uses the ordinary whole-book player timeline and needs no chapter-write endpoint. Source: [native Appbar](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/components/app/Appbar.vue), [API routes](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/routers/ApiRouter.js).

Bookmark add/edit/delete and explicit progress changes rely on `user_updated` to refresh native UI; their HTTP success callbacks do not update the user store. Playlist edits likewise rely on `playlist_added`, `playlist_updated`, and `playlist_removed`. Forward only events whose `id` or `userId` matches the authenticated Audiobookshelf account, sanitize their payload, and update the relevant store without invoking the native cross-device playback handler. Stream errors can contain FFmpeg filesystem paths, so forward an opaque session alias and a fixed public error message. Source: [bookmark UI](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/components/modals/BookmarksModal.vue), [native event handlers](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/client/layouts/default.vue), [MeController](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/controllers/MeController.js).

Production build inspection on 2026-11-19 found precompiled Vue templates, not a required runtime template compiler. Core-js bundles contain guarded `Function("return this")` fallbacks; PDF bundles contain optional eval optimizations. Those strings alone do not justify enabling `unsafe-eval`. Generated Nuxt HTML contains two inline scripts (loading error handler and public runtime configuration). The Activity build externalizes executable inline scripts into hashed same-origin assets through `native-client/externalizeScripts.mjs`, preserving their order so the app can run without `unsafe-inline`. The Activity currently disables its own global CSP, while scoped native media responses have a restrictive sandbox policy. The actual Discord wrapper policy must be checked in Discord; a successful local browser render does not prove that wrapper compatibility.

## Native Authentik/OpenID Connect flow

Use Audiobookshelf's native OIDC integration. Authentik manages the identity and Audiobookshelf returns its own access and refresh tokens with that user's native permissions. Do not assume an Authentik access token can authenticate an ABS API request.

1. Create a backend login attempt bound to the requesting activity session. Generate unpredictable state and a PKCE verifier; retain them with a short expiry and one-time completion.
2. Send `GET /auth/openid?response_type=code&redirect_uri=<activity-callback>&state=<state>&code_challenge=<S256>&code_challenge_method=S256` to ABS without following the provider redirect. Save all returned ABS cookies in the private attempt, including its Express session and `auth_method=openid-mobile`.
3. Open the returned provider authorization URL outside the Discord iframe. Authentik returns to the ABS `/auth/openid/mobile-redirect`. ABS checks its ten-minute state map and redirects to the allowed activity callback with `code` and `state`.
4. After validating the activity's own callback binding, exchange with `GET /auth/openid/callback?code=<code>&state=<state>&code_verifier=<verifier>` on ABS, using the saved ABS cookies. ABS performs the provider exchange and native user matching; its JSON contains `user.accessToken` and `user.refreshToken`.
5. Consume the attempt once. Return only an activity connection to the original session. Keep ABS cookies, codes, verifier, and tokens on the backend.

The activity callback URI belongs in Audiobookshelf **Allowed Mobile Redirect URIs**. Authentik registers the ABS **mobile redirect** URL, not the activity callback. This mobile PKCE flow supports HTTPS app callbacks as well as custom mobile schemes. The ordinary web flow enforces a same-origin callback and is unsuitable for an unrelated activity origin. Source: [OidcAuthStrategy](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/auth/OidcAuthStrategy.js), [Auth routes](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/Auth.js), [official Authentik integration guide](https://integrations.goauthentik.io/media/audiobookshelf/).

ABS builds the provider redirect origin from the HTTP `Host` header and HTTPS detection (`req.secure` or `x-forwarded-proto` containing `https`). It does **not** read `x-forwarded-host`. A backend internal-address alias must set the approved public `Host` and protocol for OIDC requests, or use the public ABS URL directly. The `authOpenIDSubfolderForRedirectURLs` setting contributes the callback path. Do not derive trusted forwarding headers from arbitrary browser input. Source: [requestUtils.js](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/utils/requestUtils.js), [OidcAuthStrategy](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/auth/OidcAuthStrategy.js).

Local login is `POST /login` with `{username,password}` and `x-return-tokens: true`. Refresh is `POST /auth/refresh` with `x-refresh-token`; it returns rotated `user.accessToken` and `user.refreshToken`. `POST /logout` accepts `x-refresh-token`, invalidates that session, and returns `{redirect_url}`. Avoid `allDevices=1` for ordinary disconnects. `POST /api/authorize` validates a bearer token and returns the native user plus browser configuration. Source: [Auth.js](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/Auth.js), [MiscController](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/controllers/MiscController.js).

The public `/status` response has `app`, `serverVersion`, `isInit`, `language`, `authMethods`, and `authFormData`. It has no stable server ID. `/ping` returns only `{success:true}`. Derive activity server identity from the validated normalized configured URL rather than inventing an upstream ID. Source: [Server.js](https://github.com/advplyr/audiobookshelf/blob/1430c9fc642d586ff91c8d4cbed20aab2c47e473/server/Server.js).

Authentik setup uses its issuer URL (`/application/o/<slug>/`) and ABS discovery auto-population. Existing users can match `preferred_username`; auto-registration is optional. If role claims are enabled, ABS expects one of `admin`, `user`, or `guest`. Community access remains a separate deliberately restricted ABS account; logging in with Authentik must preserve each personal account's own permissions. Source: [official Authentik guide source](https://github.com/goauthentik/authentik/blob/324af8563ef785f6801b6fdec98f2e5607dfaa8e/website/integrations/media/audiobookshelf/index.mdx).
